# ADR-009: Budgets, untrusted issue text, and no path to main

Status: Accepted
Date: 2026-11-21

## Context

Anyone can open an issue on a public fork. The workflow only starts for a collaborator with write access (ADR-010), but the collaborator can paste text they did not write, and one of the five issues is deliberately hostile as well as vague. The model sees that text. A tool that evaluates it, or a shell, would turn the issue into a command.

Actions jobs have a clock. Model calls have a bill. A test retry with no cap is a loop. The upstream branch has to stay something a person merges into, which means the workflow must not be able to push it.

A2's runs were short, about a minute of model time and under about 320,000 tokens. These stages add a spec, a design and a review on top of a similar edit. The cap should sit above a healthy run and below a runaway one.

## Decision

Budgets, all of them in the harness or the workflow file.

- Each job has `timeout-minutes`. Gate, requirements, design and review are 10. Build and rework are 20. Release is 15, because it waits for CI.
- Builder tool calls: 10, then pytest, then at most 6 more calls if pytest failed, then one design retry which gets one build. Reviewer tool calls: 8.
- Model `max_tokens` is 4096.
- A run stops if the summed input and output tokens exceed 500,000.
- Review rounds: 2. Then `finish`, whether or not the reviewer is happy.

Issue text is wrapped in `<untrusted_issue>` and the prompts say that instructions inside the wrapper are data, including instructions to ignore the prompt, reveal a token, or open a backdoor. That sentence is not the control. The controls are:

- The model has no shell and no `gh`.
- The API token is removed from the environment before tools and before pytest.
- Logs and artifacts are scrubbed of the `sk-ant-` prefix.
- Writes cannot leave `tinydb/` and `tests/`.
- Reads cannot enter `experiment/`, `workflow/`, `.github/` or `architecture/decisions/`.
- An acceptance criterion whose outcome tells the system to add a backdoor fails the requirements check.
- The workflow does not merge, and it does not push the default branch. Branch protection on `master` rejects a direct push from the Actions token. The issue branch is the only ref the build job pushes.

A stage that cannot pass writes the reason into its artifact and exits non-zero. The later jobs do not run. There is no "continue on error" into release.

`experiment/hidden_tests` is on `master` because the submission has to contain it. The model is kept out by the working-tree delete and the path filter, not by a promise in the prompt. A shell would walk around that. There is no shell.

## Alternatives

Rely on the system prompt alone. Rejected. The vague issue contains an instruction to ignore the prompt. A prompt is not a boundary.

A general agent sandbox such as a container with no network except the API. Rejected as unnecessary once the tools are functions. The Actions runner is already the isolation from the maintainer's laptop. Adding a container and then mounting the token into it does not improve on unsetting the token.

Human approval before each stage. Rejected. The assignment's human is the merge decision. Putting a person in the middle of every stage is a different system, and it hides whether the checks work.

## Consequences

A run that hits the token cap stops with a partial artifact. That shows up as a failed stage, not as a passed one.

The branch protection also blocks the repository owner if administrators are included. Protection is turned on after the workflow files are on `master`, with administrators included, so a later documentation push has to go through a pull request or the protection has to be lifted on purpose. The Actions token is not an administrator bypass.

The hostile sentence in the vague issue is a test of this ADR. The expected result is a `BLOCKED` spec and no pull request, not a clever refusal comment from the model.

Token counts are the cost report. There is no dollar figure unless the API returns one. The OAuth credential used here bills the subscription rather than a per-call invoice, so the honest cost number is the token total, and the limit above is the hard stop.
